# LibreDCM anomaly list

| | |
|---|---|
| Document | DHF-DCM-ANOM |
| Status | **DRAFT** (started 2026-11-10). Living list; reviewed at every release (release checklist) |
| Purpose | Known anomalies (defects, deviations, weaknesses found by testing, review or scanning) with a safety impact assessment, as required by IEC 62304 §5.8.2/§9 and the FDA *Content of Premarket Submissions for Device Software Functions* (unresolved anomalies list) |

Each anomaly becomes a GitHub issue (template *anomaly*) when the repository
work is pushed. Safety impact uses the hazards in `risk-management.md`.
Status: `Open`, `Fixed (branch/PR)`, `Accepted (rationale)`.

| ID | Found (date, how) | Description | Hazard / safety impact | Status / resolution |
|---|---|---|---|---|
| ANOM-001 | 2026-11-10, SAST (gosec G115) | `dcm.Part10` wrote 16-bit lengths for File Meta values without a bound; a value over 65,535 bytes would produce a Part 10 file that cannot be read back, after a success status | HAZ-003/HAZ-001 (archived image unreadable). Low likelihood: the filesystem store fails first on such names; S3 does not | Fixed on `qms/retro-dcm`: Part10 refuses unencodable or empty identifiers (DCM-SRS-018, `TestPart10RefusesUnencodableMeta`). Open question for Patrick: refuse UIDs longer than the 64 bytes PS3.5 allows? Today they are archived as received |
| ANOM-002 | 2026-11-10, design review of the index (class-C unit) + probe test | **Silent patient reassignment.** The study row is upserted with the demographics of the newest instance (`ON CONFLICT (study_uid) DO UPDATE SET patient_id=…`). If instances of one Study Instance UID arrive with different Patient IDs (mis-registration at the modality, a corrected resend, a UID collision), every instance of the study moves to the new patient in C-FIND results, the old patient shows no study, and nothing is logged. The archived files keep their own header, so index and file disagree. Confirmed with a probe on SQLite 2026-11-10 | **HAZ-013 (with HAZ-002): wrong-patient association** (images found under the wrong patient, prior missing under the right one). Severity S3 | Fixed on `feat/patient-conflict` (issue #14): conflicts detected in the index transaction, first association kept, conflicting instances held (DCM-SRS-070…079; `TestUpsertNeverReassignsStudy`, `TestConflictQuarantineHidden`) |
| ANOM-003 | 2026-11-10, design review of the filesystem store | `blob.FS.Put` fsyncs the temporary file but not the directory after the rename. After a power loss or kernel crash the rename can be lost although the success status was sent | HAZ-001 (image missing after power loss). Needs power loss at the wrong moment | **Open.** Proposed fix: fsync the parent directory after rename (small change, strengthens a risk control) |
| ANOM-004 | 2026-11-10, design review of the index | SQLite runs with `journal_mode=WAL` and `synchronous=NORMAL`. SQLite documents that a transaction committed this way can roll back after a power loss or OS crash (it is durable only against an application crash). The success status may already have been sent | HAZ-001 (instance archived but missing from the index, so not queryable; no re-index tool exists). Workstation and single-node installs only (PostgreSQL is not affected) | **Open.** Proposed: `synchronous=FULL` (some write-latency cost; measure) and a re-index-from-storage tool |
| ANOM-005 | 2026-11-10, verification of DCM-SRS-053 | On shutdown, open associations are closed at once; in-flight C-STOREs are aborted, not finished. The aborted instance's file can remain in storage without an index row. `shutdown_timeout` applies only to the admin HTTP server | No false success status (verified by `TestGracefulShutdown`), so HAZ-001 is controlled; the sender retries. Leaves orphaned files (storage use only) | **Accepted for now.** Optional improvement: stop accepting, let in-flight operations finish up to `shutdown_timeout`, then abort. Wording of DCM-SRS-053 ("finishing or cleanly aborting") already allows the current behaviour |
| ANOM-006 | 2026-11-10, design review | Part 10 files are written without (0002,0016) Source Application Entity Title: `store.go` passes an empty source AE. The calling AE is recorded in the index and events (DCM-SRS-017) | None for safety; reduces traceability inside the file | **Open, low.** Proposed: pass the calling AE title |
| ANOM-007 | known since 0.1 (DEVELOPMENT.md §11 item 6) | Implementation Class UID `1.2.826.0.1.3680043.10.541.1` belongs to gonetdicom's root, not to Libre Systems | Conformance/labeling; no safety impact | **Open, blocked** on the UID root (card P01) |
| ANOM-008 | 2026-11-10, fuzzing (`FuzzCFindIdentifierBytes`, crasher `testdata/fuzz/FuzzCFindIdentifierBytes/0a5a4d982be1e47a`) | A C-FIND identifier containing a command (0000,xxxx) or file-meta (0002,xxxx) element was echoed into the response. The response could not be encoded (`Command Set elements (0000,eeee) are not allowed`), so the query failed and the association was dropped. Any allowed peer could trigger it | HAZ-004 (query service interrupted for that association) and HAZ-002 (no results returned). No effect on stored data | **Fixed on `qms/retro-dcm`:** `buildResponse` ignores group 0000/0002 elements. The crasher is kept as a regression seed; removing the fix makes it fail again (checked 2026-11-10) |
| ANOM-009 | 2026-11-10, detailed design review + probe test (SQLite) | **Series moved between studies.** The series row is upserted with `study_uid` of the newest instance. If a Series Instance UID arrives under a second study (UID collision or mis-registration), the series and all its instances are listed under the new study and patient at the series level, while at the image level the earlier instance still shows its original study. Probe: series SE1 (S1/P1, then S2/P2) → series level "SE1, study S2, patient P2, 2 instances"; image level "I1 → S1", "I2 → S2". Nothing is logged | HAZ-013 (with HAZ-002): wrong-patient association for the earlier instances; inconsistent query results between levels. Same root cause class as ANOM-002 | Fixed on `feat/patient-conflict` (issue #14) with ANOM-002 (`TestUpsertNeverMovesSeriesOrInstance`, `TestConflictQuarantineHidden`) |
| ANOM-010 | 2026-11-10, detailed design review | C-GET final response reports every sent sub-operation as *Completed*: gonetdicom v0.17 does not return the requestor's per-store status to the handler, so a store the requestor refused is still counted as completed | Low: the requestor is the C-STORE SCP of these sub-operations and knows its own results; no data is lost or changed. HAZ-002 (misleading count) only | **Open, low.** Fix in the fork when C-GET reports the negotiated syntax and per-store results (same fork item as compressed C-GET) |
