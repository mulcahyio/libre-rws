## Summary

The first release under the new quality-management process, and the first
with the LibreDCM name. It adds clustering building blocks, security
controls, S3 storage and licensing for official builds. Licensing can
**never** stop DICOM services.

## Highlights

| Area | What's new |
|---|---|
| Naming | Program `LibreDCM`, image `libre/dcm`, settings `LIBRE_DCM_*`, events `libre.dcm.*`. Old `RWS_*` settings still work (with a warning), and events are also published under the old subjects |
| Reliability | Event outbox: a message-bus outage delays events but never loses them. Consistent backup while running (`-backup`). HAProxy retries on another node when one fails |
| Storage | S3 / S3-compatible object storage, with upload integrity checks |
| Security | Calling-AE allow-list (AE, AE@IP, AE@CIDR); admin token; HTTPS admin endpoint; DICOM TLS; structured audit log; patient IDs can be left out of events and audit records |
| Queries | Case-insensitive patient names (incl. accented letters), StudyTime ranges, correct UTF-8 character set in responses |
| Operations | Live reload of destinations and the allow-list (SIGHUP) |
| Installer | Asks storage (local/S3), TLS (off/self-signed/own files) and patient-ID options; upgrades 0.1.x installs in place (Windows, macOS, Linux) |
| Licensing | Official builds need a LibreKey licence (annual or perpetual, 30-day grace). After the grace period: hourly admin reminders and blocked config reloads until an administrator runs `license-ack`. **Images keep flowing in every licence state** |
| Quality system | Requirements, risk, cybersecurity and SOUP files; trace matrix; CI quality gates; SBOM; coordinated disclosure policy ([SECURITY.md](../../SECURITY.md)) |

Full list: [CHANGELOG](../../CHANGELOG.md).

## Upgrading from 0.1.1-beta.1

Run `LibreDCM.sh upgrade` / `LibreDCM.ps1 upgrade`. Settings are renamed
(a backup of `.env` is kept), the old container is removed, the data volume
is kept and the index schema upgrades from v1 to v3 on first start.

## Known issues and limits

- No storage commitment, patient update/merge (IHE PIR), mutual TLS or ATNA
  syslog yet (planned; see the IHE plan).
- C-GET serves uncompressed images only.
- 3 active requirements still lack automated tests (DICOM TLS listener,
  graceful shutdown, metrics); they are tracked on the QMS board.
- Windows `license-ack` not yet tested on a Windows host.
- Release tag and image are not signed yet.
