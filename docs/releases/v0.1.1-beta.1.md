## Summary

This is the first published release of rws-dicom, the DICOM module of RWS.
It receives, stores, indexes, queries and sends medical images over the DICOM
network protocol. This release adds a workstation package that installs the
module as a single Docker container on one PC.

The module is a beta. Use it for evaluation and testing with non-production
or anonymised data only.

## What's included

| Area | Contents |
|---|---|
| DICOM services | C-ECHO, C-STORE (all standard storage classes, compressed data kept as received), C-FIND (patient/study/series/image), C-MOVE (streaming), C-GET (uncompressed only) |
| Operations | `/healthz`, `/readyz`, `/metrics` (Prometheus), `/version` on port 8081; built-in container health check |
| Deployment | Workstation install (Windows/macOS/Linux), single node (`make up`), 3-node cluster with PostgreSQL, NATS and HAProxy (`make cluster`) |
| Documentation | [README](../../README.md), [Development document](../DEVELOPMENT.md), [Workstation install guide](../../deploy/workstation/INSTALL.md), [CHANGELOG](../../CHANGELOG.md), [gonetdicom fork notes](../../third_party/gonetdicom/RWS_FORK.md) |

## Changes since 0.1.0-beta.1

- Added the missing Dockerfile, so the image, single-node and cluster builds
  now work.
- Runtime image moved to `distroless/base-debian12:nonroot` (the JPEG codec
  needs the glibc loader).
- Workstation package: `.env` settings file, `install.cmd`,
  `rws-dicom.ps1` / `rws-dicom.sh` with install, upgrade (backs up the index
  first), verify, status, logs, backup and uninstall.
- `-echo HOST:PORT` flag for a built-in C-ECHO check.
- `RWS_DICOM_REMOTE_AES` sets C-MOVE destinations from one environment
  variable.
- Beta version numbering and release documentation.

## Install

Workstation (one PC): follow
[deploy/workstation/INSTALL.md](../../deploy/workstation/INSTALL.md). On
Windows, start Docker Desktop and double-click `deploy\workstation\install.cmd`.

From source:

```bash
git clone https://github.com/StoreHouseAdmin/RWS.git && cd RWS
git checkout v0.1.1-beta.1
make test
make image          # builds rws/dicom:0.1.1-beta.1
make up             # single node: DICOM on 11112, admin on 8081
```

Check the install:

```bash
curl http://127.0.0.1:8081/version      # "version":"0.1.1-beta.1"
docker run --rm --network host rws/dicom:0.1.1-beta.1 -echo 127.0.0.1:11112
```

## Upgrade from 0.1.0 / 0.1.1 builds

0.1.0 had no working container build, so there is nothing to upgrade from in
Docker. For a workstation installed from an earlier 0.1.1 package, set
`RWS_VERSION=0.1.1-beta.1` in `.env` and run `rws-dicom.ps1 upgrade` (Windows)
or `./rws-dicom.sh upgrade`. The index is backed up before the new container
starts. The image is rebuilt from source, so the stored data and index format
do not change.

## Known issues and limitations

- **Not for clinical use.** No audit trail (ATNA), no admin endpoint
  authentication and no AE allow-listing yet. TLS is supported but off by
  default.
- If the event bus is down, images are still stored but their
  `rws.dicom.instance.stored` events are lost (counted in
  `rws_dicom_event_publish_failures_total`).
- C-GET sends uncompressed instances only and is size-capped
  (`get_max_bytes`). Use C-MOVE for compressed data.
- Events include patient ID and accession number. Keep the bus on a private
  network with TLS.
- The Implementation Class UID is still gonetdicom's root, not an RWS-owned
  root.
- The workstation index is SQLite and must be on a local disk. The installer
  refuses network paths.
- Clusters need a shared volume for image storage; S3/MinIO is not available
  yet.
- The RWS license has not been decided. Third-party licenses are in
  [NOTICE](../../NOTICE).
